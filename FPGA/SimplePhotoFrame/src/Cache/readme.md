# 概要
cache.v は、キャッシュメモリモジュールである。

# キャッシュ対象となる DRAM の仕様
キャッシュ対象となる DRAM は、byte単位のアドレスが 23bit の 8MB。
データ幅は、32bit であり、8word のバーストアクセスである。
従って、byte単位のアドレスの下位 5bit は指定できない。

# キャッシュスペック
キャッシュメモリは、512byte である。
16WAY assciative cache である。
読み書きするコントローラーは、16bit 1word 単位で読み書きできる。
従って、アドレスは 23bit のうち、[22:1] の範囲を指定できる。
キャッシュラインサイズは、32bit 8word (=32bytes) である。
32bit の中にはリトルエンディアンで詰められる。
キャッシュメモリは、32byte (キャッシュライン) が 16way なので、512byte の SRAM で構成される。
キャッシュメモリは、17bit, 128word の SRAM が 2個で構成されている。

# キャッシュメモリのアドレスの内訳
DRAM の 1word が 32bit なので、17bit の SRAM を 2instance使用する。これをキャッシュメモリ本体と呼ぶ。
SRAM0 は下位16bit, SRAM1 は上位16bit を担当する。
さらに、その各word を書き込み予約を示すフラグを格納する 1word 2bit の SRAM を 1instance使用する。これをキャッシュマスクと呼ぶ。
SRAM0 のインスタンス名は、u_cache_line0, SRAM1 のインスタンス名は u_cache_line1 である。

## キャッシュメモリ本体
|SRAMアドレス信号のビット位置|内容|
|--|--|
|[4:2]|キャッシュライン内のword位置|
|[8:5]|WAY値|

DRAMのアドレスの [22:5] が、KEY値になる。

|SRAMデータ信号のビット位置|内容|
|--|--|
|[15:0]|読み書きする16bitのデータ|
|[16]|更新フラグ|
|[17]|有効フラグ|

# TAGメモリ
16WAY なので、16instance する。
アドレスは、KEY値に対応する [22:5] の 18bit。
TAGメモリの値の内訳は、
- KEY値を示す 18bit
- プライオリティ 4bit ( 0:最も古い, 15:最も新しい )
- 更新を示すフラグ 1bit
- 有効を示すフラグ 1bit
の 24bit である。

# 書き込み処理
まず、指定のアドレスからKEY値を求める。
16個のTAGメモリのKEY値を読み出す。
16個の KEY値は、16個のWAYに対応しており、
指定されたアドレスの KEY値と一致するものがあるか 16並列で調べる。

## 一致するものがあった場合、
キャッシュメモリ本体の、一致したWAY番号に対応し、かつアドレス[4:2]が一致し、
アドレス[1] が 0ならSRAM0, 1ならSRAM1 を対象に、書き込み処理を行う。同時に、更新フラグ・有効フラグともに 1 にする。
選択されなかった側の16bit wordについては、既に保持しているデータ・更新フラグ・有効フラグを変更しない。
TAGメモリの一致したWAY番号に対応する更新フラグは 1 にする。
TAGメモリのプライオリティを、一致したWAY番号のものを 15 にし、他のWAY番号のものを 1 減らす。

## 一致するものがなかった場合、
TAGメモリの中の有効フラグが 0 のものを探す。あれば、そのWAY番号を使う。
無ければ、TAGメモリの中のプライオリティが 0 のものを探す。必ず存在するので、そのWAY番号を使い、そのTAGメモリの更新フラグが 1 なら、そのTAGメモリに対応するキャッシュラインを DRAM に書き戻す（書き戻し方は、後述）。

決まったWAY番号に対応するキャッシュラインに、入ってきたデータを書き込み、そのキャッシュライン上のwordの更新フラグ・有効フラグを 1 にする。
このとき、実際に書き込んだ16bit wordだけを有効かつ更新済みとし、反対側16bit wordは未確定のまま残す。
TAGメモリのプライオリティを、一致したWAY番号のものを 3 にし、他のWAY番号のものを 1 減らす。

## DRAM への書き戻し方
キャッシュラインの中で、更新フラグ・有効フラグともに 1 の word のみ書き戻す。少なくともいずれかが 0 の word に関しては、DQM を使ってマスクして更新しない。

# 読み出し処理
まず、指定のアドレスから HASH値とKEY値を求める。
HASH値に対応する TAGメモリを読みだす。これをKEY値とする。
4つの KEY値は、4つのWAYに対応しており、
指定されたアドレスの KEY値と一致するものがあるか 4並列で調べる。

## 一致するものがあった場合、
キャッシュメモリ本体の、HASH値に対応し、かつ一致したWAY番号に対応し、かつアドレス[4:2]が一致し、
アドレス[1] が 0ならSRAM0, 1ならSRAM1 を対象に、読み出し処理を行う。選択した16bit wordの有効フラグが 0 だった場合は、DRAMの対応するアドレスから 8word読み出して、このキャッシュラインに書き込む。この際、キャッシュライン上で有効フラグ = 0 の16bit word のみ、DRAMから読み出した値で上書きし、有効フラグを 1 にする。更新フラグは 0 のままにする。既に有効な16bit wordは保持する。そのうえで、要求されたアドレスの値を読みだして返す。

## 一致するものがなかった場合、
TAGメモリの中の有効フラグが 0 のものを探す。あれば、そのWAY番号を使う。
無ければ、TAGメモリの中のプライオリティが 0 のものを探す。必ず存在するので、そのWAY番号を使い、そのTAGメモリの更新フラグが 1 なら、そのTAGメモリに対応するキャッシュラインを DRAM に書き戻す（書き戻し方は、書き込みの場合と同じ）。
DRAMの対応するアドレスから 8word読み出して、このキャッシュラインに書き込む。この際、読み出した word はすべてキャッシュラインへ書き込み、その word に付属する有効フラグは 1 にする。更新フラグは 0 にする。

# DRAMリフレッシュについて
内部で、32ms の周期で、sdram_refresh 信号を 1 にして、DRAMリフレッシュを行う。
正し、SDRAMに対するアクセスを行っている最中はリフレッシュを行わず、32ms経過後にアクセスが止まっているタイミングでリフレッシュ信号を出す。
リフレッシュ動作中は、SRAM へのアクセスは一時中断して、リフレッシュ完了後に開始する。

# フラッシュについて
bus_valid = 1 のときに、bus_flash 信号が 1 の場合、bus_write の値にかかわらず、キャッシュメモリのフラッシュ要求として処理する。
すべての TAGメモリを確認して、有効フラグと更新フラグがともに 1 のものがあれば、DRAM に書き戻す。書き戻し方は、書き込みの場合と同じ。その後に、その有効フラグと更新フラグを 0 にして、キャッシュメモリには有効な値が残っていない状態にする。
フラッシュ中は、bus_ready = 0 として、フラッシュ完了後に bus_ready = 1 にする。

# バスの仕様（コントローラー側）
|信号名|方向|内容|
|--|--|--|
|bus_address[22:1]|入力|DRAMのアドレス|
|bus_write|入力|1:書き込み, 0:読み出し|
|bus_wdata[15:0]|入力|バス書き込みデータ|
|bus_flash|入力|1:キャッシュフラッシュ要求|
|bus_valid|入力|1:バスアクセス要求|
|bus_ready|出力|1:バスアクセス受理|
|bus_rdata[15:0]|出力|バス読み出しデータ|
|bus_rdata_valid|出力|バス読み出しデータ有効|

bus_address, bus_write, bus_flash, bus_wdata を任意のタイミングで確定させ、bus_valid=1 になると、「コントローラーから bus_address に対して読み書き、またはキャッシュフラッシュを要求している」という意味になる。
これに対して、cache.v は、bus_ready=1 で応答する。コントローラーは、bus_ready=1 を確認すると、次のサイクルで bus_valid=0 にして、バスアクセス要求を終了する。

|要求の種類|bus_write|bus_flash|
|--|--|--|
|読み出し|0|0|
|書き込み|1|0|
|キャッシュフラッシュ|-|1|

要求の種類は上記のとおりである。
読み出し要求の場合、cache.v は bus_ready=1 に変化したサイクル以降で、読み出した結果を bus_rdata に出力し、bus_rdata_valid=1 にする。コントローラーは、bus_rdata_valid=1のタイミングの bus_rdata を読み出し結果として受領する。
キャッシュ内に見つかった場合や、見つからずに DRAMから読み出した結果を返す場合があるため、bus_ready=1 に代わったタイミングの次のサイクルから bus_ready=0 にして、bus_rdata_valid=1 にした次のサイクルに bus_ready=1 に戻す。

書き込み要求の場合、cache.v は、bus_ready=1 に変化したサイクルに得られた bus_wdata の値をキャッシュメモリへ書き込む動作に移る。キャッシュメモリへの書き込みの動作は、「書き込み処理」で説明したとおりである。

# バスの仕様（SDRAM Controller側）
cache.v と ip_sdram は、32bit 8word バーストの bus_* インターフェースで接続される。

|信号名|方向|内容|
|--|--|--|
|sdram_address[22:5]|出力|32bit 8word バースト先頭アドレス|
|sdram_write|出力|1:書き込み, 0:読み出し|
|sdram_refresh|出力|1:リフレッシュ要求|
|sdram_valid|出力|要求有効|
|sdram_ready|入力|要求受理|
|sdram_wdata[31:0]|出力|書き込みデータ|
|sdram_wdata_mask[3:0]|出力|byte単位書き込みマスク。1:書き込み対象外, 0:書き込み対象|
|sdram_wdata_valid|出力|書き込みデータ有効|
|sdram_rdata[31:0]|入力|読み出しデータ|
|sdram_rdata_valid|入力|読み出しデータ有効|

sdram_valid=1 のとき、ip_sdram は最優先で sdram_refresh=1 かどうかを判定する。sdram_refresh=1 の場合は、sdram_write の値にかかわらず SDRAM リフレッシュ要求として扱う。

sdram_valid=1, sdram_refresh=0, sdram_write=1 の場合は書き込み要求であり、sdram_ready で要求が受理された後、cache.v は 8clock 連続で sdram_wdata/sdram_wdata_mask/sdram_wdata_valid を出力する。

sdram_valid=1, sdram_refresh=0, sdram_write=0 の場合は読み出し要求であり、sdram_ready で要求が受理された後、ip_sdram は 8clock 連続で sdram_rdata/sdram_rdata_valid を出力する。cache.v はこの 8word を取りこぼさずに受信しなければならない。

cache.v が 16bit 入力を 32bit 出力へ変換する都合上、sdram_wdata_mask は 0000, 0011, 1100, 1111 の4パターンのみを使用する。

bus_ready は、要求を受けられるタイミングは 1 を出し続け、ウケられないタイミングは 0 に落とす。
読み出し処理は、キャッシュヒットの場合は短い処理時間で読み出し結果を返すが、DRAMに読みに行った場合は時間がかかる。読み出し結果の順番が崩れないように、必要に応じて bus_ready を 0 にして、追い越さないようにするように実装しなければならない。

# リセット直後時の初期化処理
リセットが解除された後、TAGメモリの有効フラグ・更新フラグをすべて 0 にする初期化処理を行う。その間、bus_ready=0 にして、要求を受け付けない。
キャッシュラインの方の有効フラグ・更新フラグは、この時点でいじる必要はありません。キャッシュラインの有効フラグ・更新フラグは、TAGメモリの有効フラグ・更新フラグが 1 のときにのみ意味を持つため、TAGメモリの有効フラグ・更新フラグが 0 のときは、キャッシュラインの有効フラグ・更新フラグは無視されます。

# フラッシュとリフレッシュの優先順位
同時に発生した場合は、リフレッシュが優先である。
どちらが早く発生し、動作中に他方が来た場合は、後から発生した方が待機して、先に動いている方が完了してから動き始める。

# プライオリティ
有効フラグ = 0 の場合の、プライオリティビットは無効です。

# 無効WAY が複数ある場合
無効WAY を探しているときに、該当が複数ある場合は、若い番号から順番に使用する。
